## 1.1 LLM 是什么，怎么来的

**大语言模型（LLM）= 在海量数据上预训练的超大规模深度学习模型。**

训练数据来源：网页、书籍、文章、研究论文、代码，加上授权数据源和人工整理的数据集。研究者发现，只要数据量足够大，这些系统就能"涌现"出对语言的理解能力、知识积累能力，甚至一定程度的推理能力。

### 训练数据规模的演进

| 模型 | 年份 | 训练数据量 | 数据来源 |
| --- | --- | --- | --- |
| BERT | 2018 | ≈ 33 亿词 | BookCorpus（8 亿词）、英文维基（25 亿词） |
| GPT-3 | 2020 | ≈ 3000 亿 token | Common Crawl、WebText2、书籍、维基 |
| LLaMA 1 | 2023 | ≈ 1–1.4 万亿 token | 公开网络数据与整理语料（Common Crawl、GitHub、维基、书籍等） |

结论很直白：**训练数据越多越好**。

### 📌 BERT 的突破

BERT 之前，NLP 模型难以理解复杂句法。Google 研究者做了两件事：

1. **掩码训练**：随机遮住句子里的词，让模型猜。模型被迫关注空白**前后**的整个句子（这就是 Bidirectional 的含义）。
2. **句子顺序预测**：打乱句子顺序，让模型判断两句是否相邻。

BERT 由此在问答、摘要等任务上取得惊人准确率，直接推动了今天的 LLM 浪潮。

### 为什么我们不自己训练

自己训练一个 LLM 的算力成本在 **几十万到数百万美元** 之间。好消息是：各家公司在疯狂发布**闭源模型**（收费）和**开放权重模型**（open weight，类似开源），而我们作为开发者，通过**API 和 SDK** 就能用上它们。

> **📌 开源（Open Source） vs 开放权重（Open Weight）**
>
> - 开源软件：代码可自由查看、修改、分享。
> - Llama 3.2 这类模型叫 **open weight**：训练好的**参数（权重）**公开了，但完整源码、数据集、训练过程不一定公开。
> - 所以 Llama 3.2 **不是真正的开源**，其许可证还限制再分发和某些商业用途。

## 1.2 文本是怎么生成出来的

### 基本循环：预测下一个 token

模型不断预测"序列中最可能出现的下一个词"，一遍又一遍，直到生成结束。每个词叫一个 **token**（token 不完全等于词，但先这么理解没问题）。

以 "Who are the Beatles?" 为例：

| 上下文（Context） | 预测出的 token |
| --- | --- |
| `Who are the Beatles?` | `The` |
| `Who are the Beatles? The` | `Beatles` |
| `Who are the Beatles? The Beatles` | `are a` |
| `Who are the Beatles? The Beatles are a` | `rock` |
| `Who are the Beatles? The Beatles are a rock` | `band` |
| ... | ... |

**Prompt 提供初始上下文**，模型预测最可能的下一个 token，把它追加到上下文里，再预测下一个……

- 这种逐步预测的方式叫 **自回归（auto-regressive）**：每个新 token 都基于它之前的全部 token 生成。
- 模型在拿到新的、未见过的数据（对 LLM 而言就是 prompt）时预测输出的过程，叫 **推理（inference）**。

**推理能力 = 泛化能力**，这正是 AI 有用的原因：训练一次，之后就能对全新输入做出反应。这是传统编程从未做到过的。

> 💡 你不需要理解 Transformer 架构才能用好 LLM。但如果好奇，可从 Vaswani 等人的论文 *"Attention Is All You Need"* 开始。

## 1.3 AI vs 传统逻辑

| | 传统编程 | AI 模型 |
| --- | --- | --- |
| 基础 | 布尔逻辑 | 统计/概率 |
| 输出 | **确定性**：同一输入必得同一输出 | **概率性**：同一 prompt 两次调用结果可能不同 |
| 灵活性 | 只能做你显式编写的任务，无法适应新场景 | 能处理复杂规则，极其灵活 |
| 失败方式 | 意外输入 → 校验失败或报错 | 意外输入 → 可能给出看似合理的错误答案 |

**这是判断"该不该用 AI"的起点：**

1. 你的业务能否容忍**响应的可变性**？即便 prompt 写得再好，token 生成依然基于概率。
2. 测试可能证明模型有 99.9% 的正确率——这也许比人类还准，但**剩下 0.1% 依然是错的**。你必须考虑一个错误答案的影响，以及如何处理。

> **📌 什么时候需要 Human in the Loop（人在回路）**
>
> 决策越关键，越需要人来核验 AI 的输出。生命攸关的系统是最明显的例子：只要有一丝可能导致死亡或重伤，几乎必然需要人在回路。

## 1.4 LLM 的多才多艺

模型并没有为你的具体请求专门训练过。它的能力来自两步：

1. **预训练（pretraining）**：在多样文本上学习一个与任务无关的通用技能——预测下一个 token。
2. **指令微调（instruction-tuning）**：用示例训练它遵循指令、给出有帮助且格式良好的回答。

于是靠一个清晰的 prompt（有时加几个示例），**同一个模型就能适配许多任务，无需重新训练**：

- 写作与编辑（邮件、草稿、改写）
- 摘要（文章、报告、会议记录）
- 分类与抽取（打标签、提取关键字段）
- 翻译
- 推理（解释步骤、拟定方案）
- 编码（片段、重构、测试）
- 聊天机器人与 AI 助手

## 1.5 必须正视的局限

AI 研究的终极目标是通用人工智能（AGI）。**LLM 不是 AGI**——至少现在还不是。

> ⚠️ 别掉进"手里拿着锤子，看什么都像钉子"的陷阱。我们的职责是基于**具体业务问题**做出明智的技术选型。

### 局限 1：训练知识有截止（Limited Training Knowledge）

模型的内置知识被**训练数据截止日期**框死。它不知道截止日之后的事实，也完全不知道你的私有数据——**除非你在 prompt 里提供**。它会对最新新闻、专有信息、高度专业的话题给出自信但过时或残缺的答案。

**解法：在推理时把缺失的上下文放进 prompt 里** —— 这叫 **AI grounding（接地/落地）**。

例如客服场景，把知识库文章塞进 prompt：

```text
Instruction: Only use the following articles to answer the question.

Context: Knowledge base articles
  - How to reset your password
  - Logging in with a password and MFA

Question: I'm having password issues. Can you help me log in?
```

> 第 8 章的 **RAG（检索增强生成）** 就是"只提供真正需要的上下文"的精准策略。

### 局限 2：幻觉（Hallucinations）

如果模型没被训练过你问的东西，它仍然会**基于见过的模式**预测一串 token 来回答，语气笃定，甚至编造事实。

书里的类比很妙：你和别人聊天，自以为完全懂对方在说什么，自信地给出精彩见解，然后对方看你像看外星人——你把记忆碎片拼成了并不适用的东西。

幻觉也源于 LLM 的概率本质：即便是高概率 token，在特定上下文下也可能是错的。**幻觉永远可能发生**，Part II 会讲一系列缓解策略。

### 局限 3：模型偏见（Model Bias）

训练数据里已经包含人类偏见和盲区。如果数据偏向某种立场（比如以英语、某地区内容为主）或重复刻板印象，模型就会复现这些模式。

这不是模型"选择"不公平，而是**它在照搬所见**。模型学的是语言模式，不带道德或伦理判断。

**对策**：加过滤、调整 prompt，或者微调模型。

### 局限 4：多步推理（Multi-Step Reasoning）

LLM 不像人那样"思考"问题，它只是按模式生成下一个可能的词，**没有计划**。因此它会：

- 跳步骤、混淆事实、做出"看起来对但其实不对"的自信跳跃
- **误差累积**：早期一步错，后面全建立在错误之上
- 长 prompt 让情况更糟：重要细节被淹没，模型丢失前文，用猜测填补空白而不是主动询问
- **缺乏可靠的自检**：不知道自己错了，对提问措辞敏感，除非你强制要求，否则不会验算数学或逻辑
- 跨轮次没有真正的工作记忆，长任务中上下文会漂移

> 第 5 章会讲处理多步推理的 prompt 技巧。

## 1.6 提升 LLM 效果：四层策略金字塔

LLM 本质上是个**黑盒**——我们不知道它到底训练过什么。对任何预训练模型，都得**实验**才知道它开箱即用够不够。老话依然成立：**Garbage in, garbage out.**

```
  便宜、简单                          灵活但可预测性低
      ▲                                       ▲
      │        ┌─────────────────────┐
      │        │   Prompt Engineering │   提示工程        ← Part II
      │        ├─────────────────────┤
      │        │  Context Engineering │   上下文工程      ← 第 4、8 章
      │        ├─────────────────────┤
      │        │     Fine-Tuning      │   微调            ← Part IV
      │        ├─────────────────────┤
      │        │    Custom Model      │   自建模型（本书不涉及）
      ▼        └─────────────────────┘
  更耗时、更贵                        更聚焦、更精确
```

### Prompt Engineering（提示工程）

需要创造力和反复试错。目标是写出提供**上下文、指令、示例**的 prompt，让 LLM 理解你的意图并产出理想输出。

**永远从这一层开始**——最简单、最省钱。效果有希望但精度不够时，再往下走。

### Context Engineering（上下文工程）

= 提示工程 + 高效管理 prompt 内上下文所需的系统组件。

> Andrej Karpathy（前特斯拉 AI 高级总监、OpenAI 联合创始人）：
>
> "人们把 prompt 理解成日常给 LLM 的简短任务描述。但在任何工业级 LLM 应用里，**上下文工程是一门精细的艺术与科学：用恰到好处的信息填满上下文窗口，以支撑下一步**。"

**上下文窗口（context window）** 定义了能发给 LLM 的 prompt 大小上限（第 4 章详述）。关键原则：

- 只放它**需要的事实**（文档片段、检索结果、记忆）
- 按**清晰的顺序**排列
- 多轮场景（聊天机器人、agent）尤其重要——对话历史能迅速塞满上下文窗口

### Fine-Tuning（微调）

当上下文工程也不够时：拿一个已经很强的 LLM，用**专业数据继续训练**，把它的核心能力塑造成你需要的样子（Part IV）。

### Custom Model（自建模型）

超出本书范围。**我们是 AI 厨师，用 API 和 SDK 集成预训练模型；模型的建造留给 AI 建筑师。**

## 1.7 从这里走向自主系统

传统软件按固定方式编程，任何新流程都要改代码。

**Agentic AI（智能体 AI）系统不同**：它们能自主运行——做决策、采取行动、随时间调整行为以达成目标，通过协调工具、API 甚至其他 AI 模型来完成复杂任务。

- **Agent（智能体）** 是最常见的 agentic AI 实现模式
- **MCP（Model Context Protocol）** 是为让工具、API、数据源可被 AI 模型访问而推出的开放标准

> Part V 详述 agent 与 MCP。

## 1.8 把 LLM 接入你的代码

ChatGPT 其实只是一个**界面**。你发 prompt 时，它在调用 OpenAI 的 API 与真正生成回答的 LLM 交互。

```
你 → ChatGPT（界面） → OpenAI API → LLM (GPT-5.x) → 响应
```

本书接下来会：

- 通过 **Ollama API** 连接本地运行的开放权重模型 **Llama 3.2**（Meta 出品，本地跑，不花钱）
- 演示低层 SDK、轻量封装、高层框架三种与模型交互的方式

同样的代码和工具可以用来实验任何预训练 LLM。**概念不变，但你的测试会揭示哪个模型效果更好、更快或更省钱。**
