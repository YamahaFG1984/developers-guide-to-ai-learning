# 第 14 章 · 用工具扩展智能体（Extending Agents with Tools）

> 对应代码：`part5/building-an-mcp-server/`

## 本章命题

> **我们已经让 AI 能搜索互联网、给出更动态的响应。但这仍然把 AI 拴在公开可得的信息上，本质上是在一个扩展了的聊天界面里运作。**
>
> **真正的能动性（agency）要求能与 LLM 通常无法直接访问的资源交互——比如一个装有私有数据的本地托管数据库。**
>
> **这正是 tools（工具）概念变得必不可少、agent 框架的力量显现的地方。这些框架让开发者能构建自定义工具，作为安全通道，给 LLM 对特定数据源和功能的受控访问。**

## 14.1 构建一个工具

**新指令：**

```
Find the latest stock price for Apple, Google and Amazon.
Convert that into a table and save it to a file.
```

> **与股价这类公开可访问的数据不同，agent 天生不具备"把信息保存到文件"这类动作的能力。这需要一套不同的技能和权限，不属于标准 agent 或 LLM 的核心功能。**

### @tool 装饰器

> **要给你的 AI agent 赋予针对你具体需求的新能力，你可以通过编写标准 Python 函数来创建自定义工具。**
>
> **`@tool` 装饰器是 smolagents 提供的便捷方式，把你的一个函数变成 agent 的 LLM 能理解和使用的工具。** 把 `@tool` 加在函数定义正上方，就注册了它，**并让它的用途和参数（通常在函数的 docstring 中描述）对 agent 的推理过程可见**，让 agent 能决定何时以及如何调用你的自定义函数来帮助解决任务。

```python
@tool                                     # ❶ 装饰器
def save_file(data: str) -> None:         # ❷ 标准 Python 函数 + 类型提示
    """                                   # ❸ docstring = 给 LLM 的说明书
    Save the data to a file

    Args:
        data: The data to save to the file

    """
    with open("investments.txt", "w") as f:    # ❹ 实际逻辑
        f.write(data)

agent = CodeAgent(
    tools=[save_file],                    # ❺ 把工具交给 agent
    model=model,
    add_base_tools=True
)
```

**❸ agent 通过我们定义的 docstring 理解这个工具能做什么。**

## 14.2 编写有效工具的最佳实践

> 编写自定义工具时，遵循这些最佳实践以确保 agent 的 LLM 能有效理解和使用它们：

| 实践 | 说明 |
| --- | --- |
| **用描述性的函数名** | 这个名字帮助 agent 的 LLM 精确理解工具做什么（如 `save_file`） |
| **总是包含精确的类型提示** | 为所有函数参数和返回值加类型提示。**这些类型提示对 agent 框架正确解读工具的预期输入输出至关重要** |
| **写全面的 docstring** | **这份描述是 agent 的 LLM 的主要说明书**，解释工具的用途和使用方式 |
| **在 docstring 中清楚描述每个输入参数** | **用平实的语言解释这些参数**，让 LLM 知道调用工具时需要提供什么信息 |

> 💡 **docstring 和类型提示不只是代码注释——它们是 LLM 用来理解自身能力的必要"说明书"。**

---

## 14.3 工具复用的问题

> **随着你计划扩展 agent 的能力，集成越来越多的专用工具是自然的进展。**
>
> **然而这种扩展自然引出关于复用性的担忧。每次构建新 agent 都要重新创建或复制现有工具，是显著的低效。想象为每个新项目重写同样的数据库查询工具或网页抓取函数——这不仅消耗宝贵的开发时间，也让跨多个 agent 维护和更新这些工具变得繁琐。**

**三种应对方式：**

| 方式 | 评价 |
| --- | --- |
| 在每个 agent 内部构建所有必要工具 | **低效** |
| 把常用工具打包成可复用的库，跨项目导入使用 | 可行 |
| **Model Context Protocol (MCP)** | **更集成、可能更高效的方式来管理和共享工具** |

---

## 14.4 Model Context Protocol (MCP)

### 它解决什么问题

> **挑战在于：我们如何创建一种可靠且标准化的方式，让任何 agent 都能发现、理解并与任何必要的工具通信？为每一对 agent-工具编写自定义代码会很快变得无法管理。**
>
> **这正是 MCP（https://modelcontextprotocol.io）要解决的问题。MCP 提出了一套标准规则和一门通用语言，不仅使 AI agent 能无缝集成并利用外部工具和数据源，还帮助定义工具和数据源必须如何被定义。**

> **不需要独特的连接器——agent 和工具都遵守 MCP 标准，让它们能"说同一种语言"。这个协议充当桥梁，确保 agent 对信息或行动的请求以兼容工具能理解的方式格式化，工具的响应也能可理解地传回 agent。**

**MCP 运行在熟悉的客户端-服务器模型上：**

- **AI agent 作为发起通信的 client**
- **工具或数据源作为响应请求的 server**
- **协议层处理交互的技术细节**——管理消息流、把特定请求链接到对应响应、确保对话遵循既定模式

> **这种标准化至关重要：构建 agent 的开发者不必太担心他们可能想连接的每一个工具的具体技术怪癖，反之亦然。**

### MCP 架构的三个角色

| 角色 | 说明 |
| --- | --- |
| **MCP hosts（主机）** | **主要的 AI 应用**（如 LLM 驱动的桌面应用或 IDE），在 MCP 生态中发起并管理连接 |
| **MCP clients（客户端）** | **嵌在 host 应用内部，与 MCP server 维持专用的一对一连接**。充当中介，促成 host/LLM 与 server 之间的通信 |
| **MCP servers（服务器）** | **向客户端提供特定能力和信息的外部程序或服务**。负责暴露 LLM 需要的各种形式的上下文和功能 |

### MCP Server 提供的三类组件

| 组件 | 说明 |
| --- | --- |
| **Tools（工具）** | **你的 MCP client（进而 LLM）可以调用的可执行函数或能力。** 工具让 LLM 与外部系统交互、执行动作或访问不在其原始训练中的数据。**把它们想成给 AI 用的可调用函数** |
| **Resources（资源）** | **你的 MCP client 可以读取的数据源或动态内容生成器。** 资源提供 LLM 能访问并纳入其理解或响应的信息或文件，**不一定要执行动作** |
| **Prompts（提示）** | **让 server 能定义和共享可复用的 prompt 模板和结构化工作流。** 提供了标准化常见 LLM 交互的强大方式，让客户端能轻松地把这些预定义指令呈现给用户和 LLM |

### MCP 传输协议（Transports）

**Transport 是让 MCP client 和 server 之间通信成为可能的底层机制，处理消息实际如何发送和接收。**

| 传输协议 | 说明 |
| --- | --- |
| **stdio（标准输入/输出）** | 通过标准输入输出流通信。**尤其适合客户端和服务器在同一台机器上运行的本地集成**，通常经由命令行进程 |
| **Streamable HTTP** | 利用标准 HTTP。**客户端用 HTTP POST 发请求，服务器可通过 server-sent event (SSE) 流把消息发回客户端**，实现基于 Web 的实时双向通信 |

### 为什么 MCP 很重要

> **MCP server 现在几乎覆盖了每个技术领域**——从数据库和支付系统到搜索和可观测性。**这些 server 充当一个强大的层，让 AI agent 能与本来高度技术化的工具进行"对话"。**
>
> **这个能力意义深远：用户无需完全理解底层机制就能与复杂系统交互。**

**MCP 的真正威力在于，一个非技术用户（比如一位经理）可以简单地问 AI：**

```
What was my AWS spend for the last three quarters,
and plot that against the number of servers running?
```

> **AI 可以用合适的 AWS MCP server 获取账单数据和服务器历史，然后把信息缝合起来呈现结果。这把一项以前要花几个小时的任务（手动登录、在复杂控制台中导航、查询多个来源）变成了几分钟内执行完的请求。经理不需要登录 AWS，也不需要理解它错综复杂的导航路径。**

## 14.5 构建你的第一个 MCP Server

> 代码在 **Python 3.13.7** 和 **FastMCP 2.12.4** 上构建和测试。

**三个步骤：**

1. 构建一个暴露四个运算（add、subtract、multiply、divide）的 MCP server——**每个运算都带一点小扭曲**
2. 通过 **Postman** 测试
3. 与 **Claude Desktop** 集成，让 AI 使用这个 MCP server

### 特殊计算器的规则

给定两个数 `num1` 和 `num2`：

| 运算 | 实际计算 |
| --- | --- |
| `add(num1, num2)` | `num1 + num2 + num2` |
| `subtract(num1, num2)` | `num1 - num2 - num2` |
| `multiply(num1, num2)` | `num1 × num2 × num2` |
| `divide(num1, num2)` | `num1 / num2 / num2` |

> 💡 **学习新概念的方法之一就是构建一些简单甚至傻乎乎的东西。**（这样能立刻验证 AI 确实调用了你的工具，而不是自己算的。）

### 完整代码

**`part5/building-an-mcp-server/mySpecialCalculator-mcp-server.py`**

```python
from fastmcp import FastMCP

mcp = FastMCP(
    name="My Special Calculator",              # ❶
    instructions="""                           # ❷
    This is a special calculator that does some special things.
    It can add, subtract, multiply, and divide in some special ways.
    """,
)


@mcp.tool
def add(num1: int, num2: int) -> int:
    return num1 + num2 + num2


@mcp.tool
def subtract(num1: int, num2: int) -> int:
    return num1 - num2 - num2


@mcp.tool
def multiply(num1: int, num2: int) -> int:
    return num1 * num2 * num2


@mcp.tool
def divide(num1: int, num2: int) -> int:
    return num1 / num2 / num2


if __name__ == "__main__":
    mcp.run()
```

### ❶ name 参数的重要性

> **把 `name` 参数当作你代码中一个关键变量或函数来对待。你不会把函数命名为 `f()` 然后指望队友理解它做什么。同样的原则在这里适用——AI 把这个名字当作理解其根本用途的首要指令。**
>
> **模糊的名字像 `mcp_server` 迫使 AI 去猜。描述性的名字像 `PayrollReportGenerator` 或 `ImageAnalysisBot`，在 AI 处理任何一条指令之前就给了它（和未来的你）重要的上下文。**

### ❷ instructions 参数

> **这个参数是我们 server 的公开文档。把它想成用户第一次发现我们的 server 时看到的 README.md 文件或帮助文本。**

### @mcp.tool 与类型提示

> **`@mcp.tool` 装饰器由 FastMCP 库提供，它把紧随其后的函数注册为 agent 可用的工具。**
>
> **这些函数的类型提示（`num1: int`、`num2: int`、`-> int`）至关重要。FastMCP 框架用它们生成工具输入输出的 JSON schema 描述。LLM 随后用这个 schema 来在决定调用工具时正确地组织其参数。**

### 运行

**默认使用 stdio 传输协议**（调用 `mcp.run()` 时默认设置）：

```bash
python mySpecialCalculator-mcp-server.py
```

```
Starting MCP server 'My Special Calculator' with transport 'stdio'
```

## 14.6 用 Postman 测试

**Postman**（https://www.postman.com）提供了与 MCP server 交互的专用界面。

**步骤：**

1. **打开 Postman 创建新请求。** 不是典型的 HTTP 请求，而是选择 **MCP 协议类型**。
2. **配置 server 命令。** 界面里有一个字段输入运行 MCP server 的命令。**选择 stdio 传输协议**，输入 server 可执行脚本的完整路径：

```
path/.venv/bin/python
path/mySpecialCalculator-mcp-server.py
```

> ⚠️ **注意我们没用系统级 Python 来跑 server，而是引用了项目虚拟环境中隔离的 Python 解释器。**
>
> **用虚拟环境的 Python 解决了包问题：它强制系统使用项目虚拟环境中隔离的解释器，该环境包含你项目所需的特定版本的包，避免了与系统级 Python 全局包的冲突。**

3. **点 Connect 按钮。** 如果 server 启动成功，Postman 会建立连接，**你会立刻看到 server 暴露的工具列表**（例如那四个运算）。
4. **点击任一工具进行交互。** Postman 会**基于你为该工具定义的 schema（期望的输入）自动生成一个表单**。填入值点 Run，就能看到 MCP server 的响应。

## 14.7 集成 Claude Desktop

**Claude Desktop 把 MCP server 配置保存在 `claude_desktop_config.json` 文件中**，这个配置文件告诉 Claude Desktop 客户端连接哪些 MCP server 以及如何运行它们。

> ⚠️ **务必参考官方 Claude Desktop 客户端文档来确认该文件在你系统上的确切位置**（macOS 和 Windows 之间不同）**以及如何编辑的详细说明**，因为这些细节可能随软件更新而变化。

### 用 FastMCP 一键安装

```bash
fastmcp install claude-desktop mySpecialCalculator-mcp-server.py
```

```
Successfully installed 'My Special Calculator' in Claude Desktop
```

**安装后的 `claude_desktop_config.json`：**

```json
{
    "mcpServers": {
      "My Special Calculator": {
        "command": "uv",
        "args": [
          "run",
          "--with",
          "fastmcp",
          "fastmcp",
          "run",
          "<path>/mySpecialCalculator-mcp-server.py"
        ],
        "env": {}
      }
    }
}
```

### 使用

1. **启动 Claude Desktop**（如果已在运行就退出重开），开始新对话
2. **在对话设置中启用特殊计算器工具**
3. 提问：

**Prompt:**
```
Do a special addition of 10 and 10
```

**输出**：AI 调用了 My Special Calculator MCP server，返回 **30**（因为 10 + 10 + 10）✅

## 14.8 MCP 传输协议进阶

> **本章开头构建的 server 使用了 stdio，这个选择把通信限制在同一台机器上本地运行的进程之间。虽然对本地开发很高效，但这种直接连接意味着 agent 和工具必须共享同一个物理或虚拟环境。**
>
> **这种设置对只给你自己用、本地运行的工具很棒。缺点？它限于单用户，无法通过网络共享。**
>
> **要让你的 server 可通过网络访问，必须使用 HTTP transport。**

> **切换到 HTTP 把你的 MCP server 变成一个 Web 服务，可以托管在任何地方——云端或专用远程服务器。当你需要一个多个客户端能从任何地方连接的单一集中式 server 时，这是正确的选择。**

```python
mcp.run(transport="http", host="0.0.0.0", port=8000)
```

> ⚠️ **截至撰写时，Claude Desktop 不支持 MCP server 的 HTTP transport。**

## 14.9 构建带复杂 Schema 的工具

> **前面构建的 MCP server 是很好的概念验证，但它的工具用的是简单的原始输入（`num1: int`、`num2: int`）和同样简单的输出。**
>
> **这离现实相当远。我们经常要处理复杂的结构化消息作为输入和输出。为此我们需要一种可靠的机制来校验从 AI 得到的数据，也必须确保工具的响应符合可预测的输出 schema。**

### 用 Pydantic 定义结构

**`part5/building-an-mcp-server/myExpenseManager-mcp-server.py`（节选）**

```python
import asyncio
from pymongo import AsyncMongoClient
from pydantic import BaseModel, Field
from datetime import datetime
from typing import List, Optional
from bson import ObjectId
from tabulate import tabulate
from fastmcp import FastMCP

mcp = FastMCP(
    name="My Expense Manager",
    instructions="This is a simple expense manager that allows you to add, find, get and count expenses",
)

uri = "mongodb://localhost:27017?directConnection=true"
client = AsyncMongoClient(uri)

database = client.get_database("test")
expenses = database.get_collection("expenses")


class Expense(BaseModel):                                        # ❶ Pydantic 模型
    _id: Optional[ObjectId] = None
    description: str = Field(description="The description of the expense")
    amount: float = Field(description="The amount of the expense")
    date: Optional[datetime | str] = Field(
        description="The date of the expense", default=None)


@mcp.tool(
    name="add_expense",
    description="Add a new expense",
)
async def add_expense(data: Expense) -> ObjectId:                # ❷ 用它作为工具输入
    try:
        print(data.model_dump())
        result = await expenses.insert_one(data.model_dump(mode="json"))
        print(f"Added expense: {result.inserted_id}")
        return result.inserted_id
    except Exception as e:
        raise Exception(
            "Unable to add the expense due to the following error: ", e)
```

**其他工具（`find_expenses`、`count_expenses`）用 docstring 描述用途：**

```python
@mcp.tool()
async def find_expenses() -> List[Expense]:
    """
    Find all expenses
    Args:
        None
    Returns:
        List[Expense]: A list of expenses
    """
    try:
        list_of_expenses: List[Expense] = await expenses.find().to_list(length=100)
        for expense in list_of_expenses:
            expense["_id"] = str(expense["_id"])
        print(tabulate(list_of_expenses, headers="keys",
              tablefmt="simple_grid", showindex="always"))
        return list_of_expenses
    except Exception as e:
        raise Exception(
            "Unable to find the expenses due to the following error: ", e)
```

> ✅ **在 Postman 中测试时，你会注意到 `add_expense` 的类型定义已被自动翻译成 MCP schema——参数类型显示为 `Expense`。**

**这体现了 Pydantic 在整本书中的一致作用：**

- 第 3 章：定义 REST API 的请求体
- 第 6 章：定义 LLM 的结构化输出 JSON schema
- 第 14 章：**定义 MCP 工具的输入输出 schema**

## 本章小结

> **本章我们从把 AI 理解为"思考者"转变为把 AI 构建为"行动者"。我们超越了简单的网页搜索和聊天界面，赋予 agent 真正的能动性——与私有数据交互并执行真实世界动作的能力。**

| 主题 | 要点 |
| --- | --- |
| **自定义工具** | `@tool` 装饰器 + 描述性函数名 + 精确类型提示 + 全面 docstring。**docstring 和类型提示是 LLM 用来理解自身能力的"说明书"** |

| **架构** | hosts / clients / servers；servers 提供 tools / resources / prompts |
| **传输** | **stdio**（本地、单用户）vs **HTTP**（网络可访问、多客户端） |
| **FastMCP** | `FastMCP(name, instructions)` + `@mcp.tool` + `mcp.run()` |
| **测试与集成** | Postman 验证工具，`fastmcp install claude-desktop` 一键集成 |
| **复杂 schema** | 用 Pydantic 模型作为工具输入输出，自动翻译成 MCP schema |

> **一封 Sales Lead 邮件到达。AI agent 认出标签后，不只是归档邮件。agent 推理道：这需要跟进。它规划了步骤、选择了工具、执行了流程——搜索公司网站、找到联系人、起草个性化外联、在 CRM 中记录互动。销售团队收到通知：新的合格线索。调研和草稿已完成，可供个性化并发送。**
>
> **瓶颈被打破了。AI 不再只是一个聪明的应答者或勤勉的邮件分拣员，它变成了真正的数字协作者。它不只是在整理收件箱，它把团队的头脑还给了他们。**

**回顾整段旅程：**

1. **第一次简单的 API 调用** —— 对一个开箱即用的 LLM，试图回答洪水般的重复支持问题。但这不够。
2. **给 AI "记忆"** —— 用向量数据库构建第一个 RAG 系统，把它接地在自己的知识上。
3. **教 AI 新技能** —— 当混乱的收件箱问题袭来，团队超越了单纯的知识检索，通过**微调**教会 AI 分类。
4. **给 AI 能动性** —— agent 推理、规划、并基于那些分类采取行动。

> **他们不需要发明一个新的基础模型。他们不是 AI 建筑师，他们是 AI 厨师。他们学会了选择正确的原料（预训练模型、RAG、微调），用恰当的技法（提示工程、工具使用）把它们组合起来，创造出强大的东西。跟随他们的旅程，你也做到了。**
>
> **这段旅程不是关于完善代码，而是关于解放写代码的人，让他们能专注于真正复杂、有创意、有战略意义、能给公司带来真正改变的事情。**

**给你的问题：**

- **什么是你版本的"收件箱问题"？**
- **哪个单一的、重复的瓶颈是你终于可以解决的？**
- **你会如何向你的经理解释 RAG 与微调的商业价值？**
- **你要试的第一个"菜谱"是什么？**

> **所以告诉我们，AI 厨师，你打算做点什么？因为现在轮到你开火了。**
