## 10.1 收集原始数据

> **准备数据集，不用看得比你自己的收件箱更远。**
>
> 如果你已经用标签或文件夹（Urgent、Receipts、Project Alpha）组织邮件，**跨大约 3–4 个不同类别选几百封邮件**。
>
> 如果邮件还没分类，花点时间手动选一个有代表性的邮件样本，给每封分配一个简单一致的标签。**目标是每个类别至少 50–100 封邮件。这个动手步骤确保你的训练数据是真实且与你的具体需求相关的。**

> 💡 **自动化提示**：与其手动复制几百封邮件（非常耗时），**你可以自动化这一步。大多数邮件服务提供商都提供开发者工具或 API**——查阅它们的文档，写个简单程序自动提取邮件和你已经应用的标签。

### 本书示例的四个标签

从一个真实个人收件箱中，**每个类别选约 100 封邮件**，选了四个类别：

- `IN_Bank`
- `IN_School`
- `US_Bank`
- `US_School`

> **这个标签选择基于真实场景**：数据集来自一个最近搬到美国的人的收件箱。**这就是为什么类别既包括印度也包括美国银行的邮件，以及印度孩子学校的信息邮件。**
>
> **训练模型不仅把邮件分类为 Bank 或 School，还进一步区分其地理来源（印度 vs 美国），提供了一个实用而有趣的用例，展示了微调对特定场景的威力。**

> ⚠️ **记住这只是一个特定邮件情境的例子。准备你自己的数据集时，你应该选择对你的邮件和你想让 AI agent 执行的特定分类任务有意义、相关的标签。你可以想出自己的场景来微调——过程是一样的。**

## 10.3 编码标签（Encoding the Labels）

> **ML 模型（包括 LLM）从根本上处理的是数值数据。** 虽然它们处理文本，但那是通过在幕后把词和字符转换成数学或数值表示来实现的——**回想 tokenization 如何把文本变成数字序列**。
>
> **对我们的微调任务，分类标签（如 `IN_Bank` 和 `US_School`）也需要是数值格式，模型才能理解和使用它们。**

### 为什么要把字符串标签转成数字

| 原因 | 说明 |
| --- | --- |
| **兼容性** | 模型建立在需要数值输入的数学运算之上 |
| **效率** | 显著提升训练时的计算效率 |
| **避免误解** | **防止模型误解字符串标签之间的任意关系** |
| **标准化** | 为 Hugging Face 等各种 ML 框架和工具标准化数据格式 |

### 本例的 ID 映射

| ID | Label |
| --- | --- |
| 0 | IN_Bank |
| 1 | IN_School |
| 2 | US_Bank |
| 3 | US_School |

> ⚠️ **分配这些数值 ID 时，唯一关键的要求是每个标签得到一个唯一的数字。**
>
> **必须记录哪个数值 ID 对应哪个文本标签——你之后需要这个映射来正确解释模型的预测。**

## 10.4 切分数据（Splitting the Data）

> **不能简单地把整个数据集都用于训练。** 如果那样做，**模型可能会记住数据而不是学习通用模式——这个问题叫过拟合（overfitting）**。
>
> 为避免这一点并获得真实的性能度量，我们**先随机化数据顺序，然后切成三个不同的集合**。

| 数据集 | 用途 |
| --- | --- |
| **Training（训练集）** | **数据的主要部分，直接用来教模型。** 模型从这些示例中学习，调整其内部机制以更好地完成特定任务（如分类邮件）。**核心学习发生在这里** |
| **Validation（验证集）** | **在模型训练期间使用。** 就像给模型做一次它没专门训练过的数据的随堂测验。**通过检查验证集上的表现，我们能监控模型学得如何、调整训练过程，并决定何时停止训练**，以确保模型在新数据上表现良好而不只是记住训练样本 |
| **Testing（测试集）** | **完全隔离，只在模型训练完成后使用。** 提供最终的、无偏的评估。**因为模型在训练或验证期间从未见过这些数据，测试集上的表现给你最真实的判断**——你微调的模型在现实世界全新邮件上会工作得如何 |

### 80-10-10 比例

- **80%** → 训练
- **10%** → 验证
- **10%** → 测试

**对每个文件要做的：**

1. **打乱/随机化**文件中的记录
2. 按 **80-10-10** 切分
3. 存成独立文件（如 `train_us_bank.csv`、`validate_us_bank.csv`、`test_us_bank.csv`）

### 手工实现（理解原理）

```python
import csv, random

random.seed(42)                                    # 固定随机种子保证可复现

path_to_in_bank = "rawData/in_bank.csv"

data_in_bank = []

with open(path_to_in_bank, "r") as f:
    reader = csv.reader(f)
    for row in reader:
        data_in_bank.append(row)

data_in_bank = data_in_bank[1:]                    # 去掉表头

# Shuffling
random.shuffle(data_in_bank)

# Splitting
train_ratio = 0.8
test_ratio = 0.1
val_ratio = 0.1

data_in_bank_length = len(data_in_bank)
data_in_bank_train_index = int(data_in_bank_length * train_ratio)
data_in_bank_test_index = int(data_in_bank_length * (train_ratio + test_ratio))

data_in_bank_train = data_in_bank[:data_in_bank_train_index]
data_in_bank_test  = data_in_bank[data_in_bank_train_index:data_in_bank_test_index]
data_in_bank_val   = data_in_bank[data_in_bank_test_index:]
```

> 💡 **为什么要打乱？**
>
> **我们打乱训练数据以防止模型学到基于示例顺序的偶然模式。这种随机化确保模型学习的是数据的特征而不只是它的序列**，帮助模型更好地泛化到新的、未见过的数据，并避免偏见。

### 合并成三个文件

按上述步骤后我们有 **12 个文件**（4 个原始 CSV × 3 个切分）。**但微调过程通常期望三个文件**：一个训练集、一个验证集、一个测试集。

**因此在开始微调前，需要把四个训练集合并打乱成一个 train 文件，四个验证集合并成一个 validate 文件，四个测试集合并成一个 test 文件：**

1. 从全部四个文件读数据
2. 合并成一个集合
3. 用 `random.shuffle` 打乱
4. 存成 CSV 文件

**结果：`train.csv`、`validate.csv`、`test.csv`**

## 10.5 用 Hugging Face Datasets 创建带标签的数据集

### 为什么不直接用 CSV/JSONL

> **问题在于关于数据本身的关键元数据会丢失**——比如每列的类型，或它能持有的有效值。
>
> 例如你分享一个 `train.csv` 文件，**接收者不会自动知道 `text` 列是字符串，或者 `label` 列虽然也是字符串但严格限定为四个特定值**：`IN_Bank`、`IN_School`、`US_Bank`、`US_School`。
>
> **没有这些嵌入的信息，你就得提供单独的文档，而文档很容易和数据脱节。**
>
> **Hugging Face 的 Datasets 库解决了这个问题**：允许你把所有重要元数据直接捕获并嵌入到数据集对象中，确保使用或分享时的一致性和清晰性。

### 加载 CSV 为 Dataset

```python
from datasets import load_dataset

dataset_in_bank = load_dataset("csv", data_files="rawData/in_bank.csv")

print(dataset_in_bank)
```

**输出：**

```
DatasetDict({                         # ❶ 数据集字典对象
    train: Dataset({                  # ❷ 只有一个 train 属性，类型是 Dataset
        features: ['text', 'label'],  # ❸ 数据的特征
        num_rows: 100                 # ❹ 记录数
    })
})
```

> 💡 **列表头自动变成了数据集的 features（特征）。**
>
> **数据集中的 feature 是一个可区分的属性或特性**——比如一个属性、一条信息或一个可能有助于理解数据的数据点。这里我们有两个 feature：`text` 和 `label`。

> ⚠️ **默认情况下，加载原始数据集时，它的数据会自动被标记为 `train`。** 我们需要把这份数据切成三个：train、validate、test。

### 切分（两阶段 train_test_split）

**`shuffle` 函数**是随机化数据集顺序的便利工具，**就像发牌前洗一副牌，确保数据顺序不会给 ML 模型引入任何偏见或非预期模式**：

| 特性 | 说明 |
| --- | --- |
| **随机化顺序** | 随机重排数据集中的示例。原始顺序丢失，**每次 shuffle 都得到不同的顺序** |
| **seed 值** | 可提供可选的 `seed` 参数，**确保用相同 seed 运行代码时得到相同的随机顺序。这对可复现性很重要** |

**`train_test_split` 把数据集分成两个随机子集：训练集和测试集。**

**要得到三个切分，分两阶段使用：**

```python
# 阶段 1：80% train / 20% temp
ds_in_bank_train_test_split = ds_in_bank['train'] \
    .train_test_split(test_size=0.2, shuffle=True, seed=42)

# 阶段 2：把 20% 的 temp 对半分成 validation 和 test
ds_in_bank_test_valid_split = ds_in_bank_train_test_split['test'] \
    .train_test_split(test_size=0.5, shuffle=True, seed=42)

ds_in_bank_split = DatasetDict({
    'train':      ds_in_bank_train_test_split['train'],
    'validation': ds_in_bank_test_valid_split['train'],
    'test':       ds_in_bank_test_valid_split['test']
})
```

**对其余数据集重复这个过程。**

### 合并四个数据集

> **需要合并成单一数据集文件，因为标准微调工具和库通常设计为使用一个主数据集文件进行训练，简化输入流程。**
>
> **合并的同时必须打乱整个数据集。打乱确保所有类别的示例在训练过程中随机混合**，防止模型被数据的原始顺序或分组所偏置，帮助模型从多样的示例序列中更准确地学习。

```python
from datasets import concatenate_datasets

ds_combined_train = concatenate_datasets([
    ds_in_bank_split["train"],
    ds_in_school_split["train"],
    ds_us_bank_split["train"],
    ds_us_school_split["train"]
])
ds_combined_train = ds_combined_train.shuffle(seed=42)

# ... 同样方式创建 validate 和 test 数据集

ds_combined = DatasetDict({
    "train":      ds_combined_train,
    "validation": ds_combined_validate,
    "test":       ds_combined_test
})
```

**打印结果：**

```
DatasetDict({
    train: Dataset({
        features: ['text', 'label'],
        num_rows: 320
    })
    validation: Dataset({
        features: ['text', 'label'],
        num_rows: 40
    })
    test: Dataset({
        features: ['text', 'label'],
        num_rows: 40
    })
})
```

### 保存到磁盘

```python
ds_combined.save_to_disk("./data/mail_dataset")
```

> 💡 **这个本地检查点是一个很好的里程碑**——它确保你不必在每次开始新的训练会话时都重跑耗时的收集和打乱步骤。

## 10.6 验证并修正标签类型

### 加载检查

```python
ds = load_from_disk("./data/mail_dataset")

print(ds)
```

```
DatasetDict({
    train: Dataset({ features: ['text', 'label'], num_rows: 335 })
    validation: Dataset({ features: ['text', 'label'], num_rows: 42 })
    test: Dataset({ features: ['text', 'label'], num_rows: 43 })

```

```python
print(ds["train"].features)
```

```
{'text': Value(dtype='string', id=None),
 'label': Value(dtype='string', id=None)}     # ⚠️ label 目前是普通字符串
```

> ⚠️ **label 目前是字符串（string）。技术上没什么错，但更好的实践是强制 label 为字符串类型且必须是这四个值之一：`IN_Bank`、`IN_School`、`US_Bank`、`US_School`。**
>
> **显式定义 label 列给你的 ML 项目增加了清晰度和类型安全。这就像给食品储藏室里的原料清楚地贴标签——你立刻知道你处理的是一个类别标记，而不是一个通用字符串，防止意外误用，就像知道糖不是盐一样。** 这种清晰度让你的代码更易理解、更不易出错。
>
> **此外，这种方式添加了有价值的元数据和上下文，像一份解释该如何解读的食谱，提供对数据结构更深的理解。**

### 修正：Cast + Align

```python
label_names = [ "IN_Bank", "IN_School", "US_Bank", "US_School" ]

label2IdMap = {
    "IN_Bank":   0,
    "IN_School": 1,
    "US_Bank":   2,
    "US_School": 3
}
```

> **Casting（类型转换）是显式指示程序把一段数据从一种特定数据类型转换成另一种的过程**（这里是把整个通用列字段变成一个结构化类型）。
>
> ⚠️ **但仅仅 cast 是不够的。** 我们的数据仍会有 0、1、2、3 作为 label 值。
>
> **`align_labels_with_mapping` 这一步确保数据集中底层的整数 ID 与你的特定标签匹配。如果你的数据集原本把 `IN_Bank` 当作 ID 3，这一步会重新映射内部表示，让 `IN_Bank` 始终映射到你字典中定义的 ID 0。**

```python
from datasets import ClassLabel

ds = ds.cast_column("label", ClassLabel(names=label_names))
ds = ds.align_labels_with_mapping(label2IdMap, "label")
```

### 保存并验证

```python
ds.save_to_disk("./data/mail_dataset_labeled")

ds_labeled = load_from_disk("./data/mail_dataset_labeled")
ds_labeled["train"].features
```

```
{'text': Value(dtype='string', id=None),
 'label': ClassLabel(names=['IN_Bank', 'IN_School', 'US_Bank', 'US_School'], id=None)}
```

## 本章小结

| 步骤 | 要点 |
| --- | --- |
| **收集原始数据** | 用真实数据（你自己的邮件）；每类别 50–100 封；可用邮件 API 自动化 |
