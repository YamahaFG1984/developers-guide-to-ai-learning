先看看电脑够不够

Ollama 使用的是量化模型（quantized model）：把模型参数的精度降低一点，换来更小的体积和更快的速度。 所以普通笔记本也能跑。本书默认用 3B（30 亿参数）版本，配置低可以用 1B 版本：

💡 SLM：小语言模型

能在普通硬件上跑的轻量模型也被叫做 SLM（Small Language Model）。 用 1B 也能跑完所有例子，只是回答会有差别 —— 这恰恰很有意思：你能亲眼看到模型规模对效果的影响。

第一步：调用 LLM（非流式）

ⓘ 本教程用 Hono 替代了书中的 Express

原书第 2 章用的是 Express。本仓库的示例已改写为 Hono： 它直接使用浏览器里就有的 Web 标准对象（Request、Response），同一份代码能跑在 Node.js、Bun、Deno、Cloudflare Workers 上， CORS、流式响应等常用功能都是内置的，不必另装包。概念和书中完全一致，只是写法更现代。 本章末尾有一张 Express ↔ Hono 对照表，方便你对照原书阅读。

  • @hono/node-server：让 Hono 应用跑在 Node.js 上的适配器

🍳 打个比方

package.json 里的 dependencies 就像菜谱上的原料清单。 只要有菜谱，随时能把原料买齐（npm install）。所以分享项目时不用带上 node_modules。 

import { Hono } from "hono";                 // ❶ 导入 Hono
import { serve } from "@hono/node-server";   //   Node.js 适配器
import { Ollama } from "ollama";             //   和 Ollama 客户端

const app = new Hono();                      // ❷ 创建应用
const ollama = new Ollama();                 // ❸ 创建 Ollama 客户端

app.get('/', async (c) => {                  // ❹ 访问根路径时执行，c 是上下文
  const modelResponse = await ollama.generate({  // ❺ 把 prompt 发给模型，等它答完
    model: 'llama3.2',
    prompt: "Can you simply say 'test'?"
  });

  console.log(modelResponse);                // 打印完整响应对象，看看里面有什么
  return c.text(modelResponse.response);     // ❻ 以纯文本返回回答
});

serve({ fetch: app.fetch, port: 8000 }, (info) => {   // ❼ 在 8000 端口启动
  console.log(`Server is running on port ${info.port}`);
});
  1. 导入工具Hono 负责路由和请求/响应；serve 把它挂到 Node.js 的 HTTP 服务上；Ollama 负责和 Ollama API 对话。
  2. 创建应用和客户端new Hono() 得到应用，new Ollama() 得到默认连接 localhost:11434 的客户端。
  3. 注册路由app.get('/', …)：有人 GET 根路径时执行处理函数。参数 c 是上下文（Context）：用 c.req 读请求，用 c.text()、c.json() 等造响应。
  4. 调用模型generate 是异步方法，await 会一直等到模型完整生成回答。
  5. 返回纯文本c.text() 自动设置 Content-Type: text/plain，告诉浏览器“别当 HTML 解析”。在 Hono 里，处理函数返回一个响应，而不是调用 send。

第二步：流式响应

为什么需要流式？

LLM 生成文本很慢 —— 一段 500 字的回答可能要十几秒。如果像上面那样等它全部生成完再返回， 用户会盯着空白页面干等。ChatGPT 的办法是生成一点，显示一点。 OpenAI 巧妙地把 LLM 的一个缺点（慢）变成了一个迷人的 UI 效果。

原理其实很自然：LLM 本来就是逐 token 生成的（第 1 章）。 流式就是 token 一生成出来就立刻打包成一个个小块（chunk）发回去，而不是攒到最后。

服务端：两处改动

第一处，调用 generate 时加上 stream: true。这时它不再返回完整结果，而是返回一个异步迭代器：

const streamIterator = await ollama.generate({
  model: 'llama3.2',
  prompt: body.question,
  stream: true                        // ← 关键：开启流式
});

第二处，用 Hono 内置的 streamText 返回一个流式响应。在回调里用 for await 逐块读取模型输出，每读到一块就 stream.write 立刻发给客户端；回调结束，响应自动关闭：

import { streamText } from "hono/streaming";

return streamText(c, async (stream) => {
  for await (const chunk of streamIterator) {   // 模型每生成一块，循环体执行一次
    await stream.write(chunk.response);         // 马上写回客户端
  }
});                                             // 回调结束 = 响应结束

streamText 会自动设置 Content-Type: text/plain 和分块传输（Transfer-Encoding: chunked），你只管往里写。

CORS 与中间件

前端（Vite 开发服务器，localhost:5173）和后端（localhost:8000）端口不同，浏览器认为它们是不同的源（origin）。 出于安全考虑，浏览器会拦截跨源请求，除非服务器用特殊的响应头明确表示“我允许”。这套规则叫 CORS（跨域资源共享）。

解决办法是用 Hono 的中间件（middleware）。中间件是包在处理函数外面的函数， 可以在请求到达你的代码之前、响应发出之后做加工。Hono 自带了 cors() 中间件，一行就能开启跨域：

本书所有示例都用了最宽松的 CORS 配置（允许任何来源），只是为了方便学习。上线前务必只允许你自己的前端域名。

完整的流式服务

JSON 请求体不需要额外的解析中间件：在处理函数里 await c.req.json() 就能拿到对象。所以这一步不用再装任何包。

import { Hono } from "hono";
import { cors } from "hono/cors";
import { streamText } from "hono/streaming";
import { serve } from "@hono/node-server";
import { Ollama } from "ollama";

const app = new Hono();

app.use(cors());                    // ❶ 中间件：处理跨域

const ollama = new Ollama();

app.post('/', async (c) => {        // 改成 POST，才能在 body 里带问题
  const body = await c.req.json();  // ❷ 读取并解析 JSON 请求体

  const streamIterator = await ollama.generate({
    model: 'llama3.2',
    prompt: body.question,          // ❸ 用户的问题就是 prompt
    stream: true
  });

  return streamText(c, async (stream) => {   // ❹ 流式返回
    for await (const chunk of streamIterator) {
      await stream.write(chunk.response);
    }
  });
});

serve({ fetch: app.fetch, port: 8000 }, (info) => {
  console.log(`Server is running on port ${info.port}`);
});

客户端发来的请求体长这样：

{ "question": "Can you tell me about the Beatles in 500 words or less?" }

用 curl 测试。注意 -N 参数：它关闭 curl 的输出缓冲，否则你看不到“逐字出现”的效果：

curl -N -X POST -H "Content-Type: application/json" -d \
  '{"question": "Can you tell me about the Beatles in 500 words or less?"}' \
  http://localhost:8000

第三步：前端读取流

浏览器的 fetch 有个很少人知道的能力：响应体 response.body 是一个 ReadableStream， 可以一块一块地读，不必等全部下载完。下面这张图把整条“流水管道”串了起来： 

let llmResponseProgress = '';

const renderResponseChunk = (chunk) => {
  llmResponseProgress += chunk || '';        // 把新的一块拼到后面
  if (llmResponseProgress) {
    setLlmResponse(llmResponseProgress);     // 更新 React 状态，页面自动重绘
  }
};

const fetchData = async () => {
  setLlmResponse('Please be patient, calling a local LLM can take some time...');

  const response = await fetch('http://localhost:8000', {
    method: 'POST',
    headers: { 'Accept': 'application/json', 'Content-Type': 'application/json' },
    body: JSON.stringify({ question })
  });

  llmResponseProgress = '';

  const reader = response.body
    .pipeThrough(new TextDecoderStream())    // ❶ 字节流 → 文本流
    .getReader();

  while (true) {
    const { done, value } = await reader.read();
    renderResponseChunk(value);              // ❷ 每读到一块就渲染
    if (done) return;
  }
};
