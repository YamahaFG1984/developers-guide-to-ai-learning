从工作流到自主智能体

到目前为止，我们的 AI 都在“说”：回答问题、生成文本、打标签。这一章开始让 AI “做”： 自己规划步骤、调用工具、根据结果调整，直到完成目标。这样的系统叫 AI Agent（智能体）。本章没有代码，先把概念理清。

本章目标

  • 理解 AI Agent 和普通聊天模型的区别
  • 记住 Agent 的三大能力：规划、使用工具、推理
  • 分清三种工作流：传统工作流、AI 工作流、Agentic 工作流

故事：瓶颈只是换了个地方

微调后的分类模型把混乱的收件箱变得井井有条：销售线索、客服请求、合作提案各归其位，雪崩被驯服了。 但分类只是第一步 —— 每个文件夹里的邮件，仍然要人去一封封跟进：

这些任务远不只是生成一段文字。每一项都需要：

  • 在不同软件之间切换，访问外部网站，执行搜索
  • 根据查到的信息做小决策
  • 用 CRM、日历、搜索引擎、邮件工具，按一定顺序编排多个步骤
🔑 问题变了

从“AI 能理解并标记这封邮件吗？”变成了 —— “AI 能对这封邮件采取行动吗？它能拿到一条销售线索，想清楚跟进需要哪些步骤（调研、找联系人、写邮件、记 CRM）， 找到执行每一步的工具，然后自己把计划执行完吗？” 团队需要的东西，不仅要能思考，还要能行动。

什么是 AI Agent

AI Agent 是一个以 LLM 为“大脑”、能自主规划、推理并执行一系列步骤来达成目标的系统。 普通聊天模型只是回应你的 prompt；Agent 接到一个高层任务，会自己想办法把它完成。

Agent 的三大能力

能力在订餐厅例子里
规划 Planning决定先搜索素食餐厅，再按评分和露台筛选，最后用工具检查能否预订
工具 Tool use用搜索工具找餐厅、用日历工具查日期、用预订工具订座
推理 Reasoning分析每一步的结果：餐厅关门了就回头换一家；订成功了就结束任务
💡 一句话

Agent 就是给一个被动的 LLM 配上一套工具和使用工具的框架，把它变成主动的、目标导向的问题解决者。

三种工作流

工作流（workflow）是为达成某个业务目标而设计的一系列相互关联的步骤：谁做什么、什么时候做、每步用到什么信息。 按照给 AI 多大的自主权，可以分成三类：

① 传统工作流

预先定义好的、基于规则的任务序列，通常用 ETL、BPM 系统或集成平台（iPaaS）实现。确定性：按固定逻辑走， 常由事件或定时触发，擅长自动化重复任务和在应用间搬数据。

弱点：刚性，难以适应变化和做复杂决策，遇到异常往往需要人工介入。

例子：按预定规则自动排序和归档文档的脚本。

② AI 工作流

结构化的线性任务序列，在预定位置使用 AI，上一步的输出是下一步的输入。 强调可预测性和控制，适合要求一致性和可靠性的流程；借助 AI 处理规则系统应付不了的细致任务。

弱点：并非完全自主，关键决策仍依赖人工监督。

例子：用 AI 做情感分析来路由客服工单，但复杂问题仍由人工客服解决。本书第 5–11 章做的基本都是这一类。

③ Agentic 工作流

工作流里加入了能自主决策、采取行动的 AI Agent。整体仍有结构，但在某些环节 Agent 可以自己选择用什么工具、怎么推进。 这引入了非确定性：Agent 的选择会因情境而不同。它能独立规划、执行、适应，利用外部工具和环境反馈达成目标，甚至随时间优化自己的流程。

代价：需要仔细监控和控制，确保 Agent 的行为与期望结果一致。

例子：一个管理旅行行程的 Agent，根据你的偏好订机票、酒店和活动，并主动应对航班变化、实时通知你。

小结

  • LLM、RAG、提示工程、微调都擅长生成回答；AI 更大的潜力在于独立行动、编排任务、和真实世界交互。
  • AI Agent = LLM 大脑 + 规划 + 工具 + 推理，接到高层任务后自己想办法完成。
  • 三种工作流：传统（无 AI）→ AI 工作流（AI 在固定位置）→ Agentic 工作流（AI 自主决定步骤）。
  • 自主性越高越灵活，也越需要监控。
