提示工程基础

你连上 LLM，发一个简单的 prompt，也许答得不错，也许不行。改了几个词，模型突然像换了一个人。 没换模型，没改代码，只是换了措辞。那一刻你就会明白：提示工程不是锦上添花，而是必需品。

🔑 本章核心

LLM 不是魔法，它只是根据你的 prompt 预测一串 token。它并不理解你的意思，它只知道你打了什么字。 提示工程就是在“你需要什么”和“模型生成什么”之间架一座桥。

本章目标

  • 分清什么问题该用代码解决，什么问题值得交给 LLM
  • 写出详细、清晰、简洁的 prompt，掌握 prompt 的五大要素
  • 理解 token、上下文窗口，以及它们如何影响成本、准确性和速度
  • 知道选模型时要权衡哪些因素
💡 边读边试

把第 3 章的 FastAPI 服务和 React 前端跑起来，本章每个 prompt 都在浏览器里亲手试一遍，感受会完全不同。

编程 vs 提示

先看一个传统函数：从邮箱地址里取出域名。

def get_email_domain(email: str) -> str:
    return email.split('@')[1]

print(get_email_domain("info@focus.dev"))   # focus.dev
print(get_email_domain(42))                 # AttributeError: 'int' object has no attribute 'split'

同样的事，用一句 prompt 也能做到：

Prompt · Llama 3.2 3B
Given an email address, you will return only the complete domain name from that email address. Email Address: info@focus.dev, Domain:
focus.dev

当然，你永远不该为这么简单的任务去调 LLM —— 又慢又贵。但这个例子说明：LLM 对语言的理解让它极其多才多艺。 而这种灵活性也意味着，如果你想限制它的回答，就得仔细下指令。

ⓘ 本书的 prompt 展示格式

书中会同时给出 prompt、回答，以及生成回答的模型（如 Llama 3.2 3B）。如果改过模型配置，会在模型名后注明。你自己跑时回答可能略有不同，这很正常。

一个真正适合 LLM 的场景：情感分析

一家创业公司想管好社交媒体上的口碑：自动判断每条提到公司的帖子是正面、中性还是负面， 把负面的顶到最前面让人跟进。这叫情感分析（sentiment analysis），本质是一个分类问题。

传统机器学习模型也能做情感分析，但真实的帖子有多种语言、有文化上的弦外之音、还有网络俚语。 这些恰恰是 LLM 的强项。

帖子（prompt 的末尾部分）Llama 3.2 的回答
My order from @AcmeCorp never arrived and customer service wasn't helpful.Sentiment: Negative
Thank you @AcmeCorp! Can't wait to try this new shampoo!Sentiment: Positive
No confiaría en @AcmeCorp.Sentiment: Negative
Everything I've seen on the @AcmeCorp website is so mid.Sentiment: Negative

完整 prompt 的开头都是 Tell me if the following statement is positive, neutral, or negative:，结尾是 Sentiment:。

别只看答案，还要看理由

西班牙语和俚语那两条真的对吗？在 prompt 结尾加一句 Explain your reasoning. 让模型说出理由：

Prompt · 让模型解释
Tell me if the following statement is positive, neutral, or negative: "Everything I've seen on the @AcmeCorp website is so mid." Explain your reasoning.
负面。① "mid" 通常带负面含义，指平庸、质量一般；② 句子语气挑剔、不屑；③ "so mid" 常用来表达轻视或无聊。
🔑 关键方法：答对 ≠ 推理对

即使答案看起来正确，推理过程也可能有漏洞，换个例子就会答错。 让模型解释推理，是验证它“不仅答对、而且理由站得住”的好办法。 如果你自己也不认识 “mid” 这个词，就该去查一下，核实模型的说法。第 5 章的思维链（CoT）会把这个技巧发扬光大。

⚠ 输出格式不稳定

上面的回答都带着 Sentiment: 前缀。你可以在代码里解析它，但换个模型格式可能变， 同一个模型不同次调用也可能变。我们需要更精确地告诉模型“怎么回答” —— 后面的提示技巧和第 6 章的结构化输出会解决这个问题。

你的需求适合用 LLM 吗？

Prompt 之所以强大，是因为 LLM 能在上下文中学习（learn in context）：就算它没专门训练过某项任务， 你也能通过提示技巧“教会”它。但要始终记住，影响输出的有三个因素：

  1. 你调用的模型的能力
  2. 它的训练数据（以及其中的偏见）
  3. 模型的配置参数（第 6 章）

每个模型对同一个 prompt 的反应都至少略有不同。如果需求看起来适合 LLM 但效果不理想，试试换模型或调配置。

📈 和真实基线比，而不是和完美比

担心 AI 不总是对？举个例子：从邮件里提取销售线索（姓名、职位、公司、电话）。 如果人工处理有 3% 出错，准确率就是 97%。你的 AI 方案如果达到 98%，它不完美，但比人强。 前提是你在足够多的真实样本上测过。

好 prompt 的三个特质：详细、清晰、简洁

作为开发者，我们其实很有优势：我们天天在做的，就是把模糊的想法变成计算机能执行的分步指令。

🔍

详细 Detailed

说清楚要模型做什么，不留误解空间。

💡

清晰 Clear

用简单直接的语言解释任务。

✂

简洁 Concise

去掉与任务无关的废话。

对比两个 prompt：

Prompt 1 · 模糊
Tell me about the Beatles in 500 words or less.
Prompt 2 · 具体
You are an expert on the history of popular music. Summarize the music career of the Beatles for someone who knows nothing about the history of popular music. Provide their accomplishments prior to breaking up and their lasting influence on popular music. Focus on the records they released, the critical and commercial reception of each record, and how it changed popular music. Explain in simple terms and keep your response under 500 words.

两个 prompt 都会得到关于披头士的介绍。但 prompt 越开放，“可接受的回答”就越多。 模型并不是在“猜”你的意思，它只是在概率上从一大片可能的回答里挑一个 —— 你没说清的地方，它会用你意想不到的方式填上。

维度Prompt 1Prompt 2
主题披头士披头士
角色（persona）—流行音乐史专家
受众 / 语言难度—完全不懂流行音乐史的人，用简单的话
时间范围—乐队解散之前
关注点—唱片、口碑与商业反响、对流行音乐的改变
长度≤ 500 词≤ 500 词

这两个都是零样本提示（zero-shot）：没给任何示例，完全依赖模型的训练数据。第 5 章会讲一个示例（one-shot）和多个示例（few-shot）的写法。

Prompt 的五大要素

写 prompt 没有唯一正确的格式，但下面这个心智框架非常好用。一个完整的 prompt 通常由这五块拼成：

一个真实例子：AI 客服

客服 prompt（标注了各要素）
[Instruction] Answer the question using only the following context: [Context] To reset your password, follow these simple steps: 1. Click on the "Forgot Password" link on the login page. 2. Enter your registered email address. 3. Check your email for a password reset link. 4. Click the link in the email (valid for 24 hours). 5. Create a new password that meets our security requirements: - At least 8 characters long - Contains uppercase and lowercase letters - Includes at least one number - Has at least one special character If you don't receive the reset email within 5 minutes, please check your spam folder or contact our support team. For security reasons, your old password will be immediately invalidated once you create a new one. [Query] Question: I'm having password issues. Can you help me log in?

这个 prompt 能用，但还有很大改进空间：

  • 指令太单薄：模型该表现得专业还是亲切？用户问了知识库里没有的东西怎么办？用户不怀好意呢？ → 后面会用 persona（角色）、不确定性处理、护栏（guardrails）来补强。
  • 边界不清楚：文章从哪开始、到哪结束？模型怎么区分指令、资料和用户问题？ → 第 5 章用分隔符解决。

上下文窗口

LLM 对单次请求能接收的文本量有上限，超过就直接拒绝。这个上限叫上下文窗口（context window），用 token 数来衡量。 下面是几个常见模型的窗口大小：

🔑 窗口大 ≠ 应该塞满

这就是上下文工程登场的地方：不要把所有东西一股脑塞进 prompt，而要有意识地筛选和整理， 让模型只看到它需要的内容，并以好用的形式呈现。下面几节会解释为什么。

Token 与分词

每个模型都有自己把文本切成 token 的方式。OpenAI 给了一个经验法则： 常见英文里，1 个 token ≈ 4 个字符 ≈ ¾ 个单词，所以 100 个 token 大约是 75 个词。 你可以在 OpenAI Tokenizer 网页上亲手试试。

用 tiktoken 数 token

import tiktoken

def count_tokens(text: str, model_name: str):
    # All OpenAI models are supported
    encoding = tiktoken.encoding_for_model(model_name)   # ❶ 拿到该模型的编码器

    # Tokenize the text
    tokens = encoding.encode(text)                        # ❷ 把文本编码成 token ID

    print(tokens)
    print(f"Number of tokens: {len(tokens)}")

model_name = "gpt-5-mini"
sample_text = "I'm having password issues. Can you help me log in?"

count_tokens(sample_text, model_name)

[15390, 4566, 6088, 6086, 13, 4101, 481, 1652, 668, 2142, 306, 30]
Number of tokens: 12
💡 模型的两个名字

代码里用的是模型的技术名 gpt-5-mini，而宣传材料里叫 “GPT-5 mini”。两者指的是同一个模型。

Token ID 是什么

输出全是数字：每个 token ID 是一小段文本的唯一编号，是模型对文本的内部表示。 模型预测的其实是这些编号，再通过一张查找表翻译回文字给我们看。 相同的片段永远对应相同的 ID，这在相同 token 之间建立了联系，也节省了存储：

别让成本失控

40 万 token 的窗口看起来很大，好像碰不到上限。但云端模型通常按 token 收费，输入和输出分开计价：

💰 单次请求成本

成本 = 输入单价 × 输入 token 数 + 输出单价 × 输出 token 数

模型窗口输入单价输出单价
GPT-5 mini400,000$0.25 / 百万 token$2.00 / 百万 token
GPT-5400,000$1.25 / 百万 token$10.00 / 百万 token
GPT-5 pro400,000$15.00 / 百万 token$120.00 / 百万 token
  1. 从便宜的开始别一上来就用最贵的模型，先试 GPT-5 mini 这类小模型够不够用。
  2. 留意“思考型”模型的隐藏开销GPT-5 pro 这类高级推理模型在输出前会先用额外的 token 做规划。这让它更擅长复杂任务，但 token 用量可能大幅增加。
  3. 监控用量看服务商的用量面板，或者直接从 API 响应里读取 token 统计。
🔮 开放权重模型不是“免费”，是“自己托管”

用 Llama、Mistral、Gemma 这类开放权重模型，没有按 token 计费，但你要自己承担算力： 一台有像样 GPU 的机器（小模型至少 8–16 GB 显存，大模型远不止）、电费，以及搭服务器、加载模型、扩缩容、保可用的时间和经验。 成本没有消失，只是换了一种形式。

塞太多，准确性和速度都会变差

就算不差钱，把所有知识库文章都塞进 prompt 也会伤害效果：

👻

更容易幻觉

正确的句子旁边摆着跑题的段落，模型可能拿无关内容来回答。

🕳

中间迷失

模型更关注长 prompt 的开头和结尾，中间的关键段落可能被忽略。

🐛

难以调试

prompt 越大，模型行为变化时越难定位原因。

速度：prompt 越长，每一步越慢

回忆第 1 章的生成循环：模型每生成一个新 token，都要处理整个 prompt + 已经生成的所有 token。 prompt 越长，每一步要算的东西就越多：

解决办法是只提供最相关的片段 —— 这正是第 8 章 RAG 要做的事。

怎么选模型

新模型层出不穷。选择时按下面几个维度过一遍：

因素要问的问题
用例问答、摘要、分类、写代码、创意写作？先搞清楚要找哪方面强的模型
托管方式托管 API（OpenAI、Anthropic）接入快、按量付费；自托管（Llama、Mistral、Gemma）控制力强，但要自己管基础设施
上下文窗口你的 prompt 大概多少 token？窗口够不够
能力推理、事实准确性、函数调用、结构化输出、多语言……
亲手测试什么都替代不了用你的真实任务并排测试：同一个 prompt 在 2–3 个模型上跑，比速度、准确性、成本
性能/成本大模型强但贵，GPT-5 mini、Claude Haiku 4.5 这类小模型也许“够用”，成本只是零头
许可证开放权重尤其要看。例：Llama 3.2 允许商用但有限制 —— 月活超 7 亿需特殊许可，且禁止在欧盟使用其多模态模型
数据隐私托管 API 会怎么用你的数据？自托管可以做到数据不出门，但需要加固每一层

你甚至可以让 LLM 帮你做一张对比表：

Provide a table comparing GPT-5 Mini, Claude Haiku 4.5, and Llama 3.2. List the model names across the table header and complete the following rows below them: - Type (example: proprietary, open weight) - Context window - Strengths (examples: structured output, reasoning) - Ideal use case (examples: agents, coding) - Hosting (example: OpenAI Hosted API, self-hosted) - License (example: commercial) Provide sources with URLs for your answer.
⚠ 一定要核对来源

模型天生带偏见 —— 这里我们在让一个 OpenAI 模型评价它的竞争对手。它也许完全公正，但请自己去验证。 这就是 prompt 最后要求“附上来源链接”的原因。网上也有各种模型排行榜（leaderboard）可以参考。

小结

  • 规则明确的问题写代码；需要语言理解的问题试 LLM。和真实基线比，而不是和完美比。
  • 提示工程是提升准确性和可靠性的第一杠杆：详细、清晰、简洁。
  • Prompt 五大要素：指令 / 上下文 / 示例 / 查询 / 输出格式。
  • 你发的每个字都会变成 token，既花时间也花钱。
  • 大 prompt 会稀释相关性（中间迷失）并拖慢生成，所以要只提供最相关的片段（第 8 章 RAG）。
  • 选模型是一场平衡：用例、托管、窗口、能力、成本、许可、隐私，最后用真实任务测。
