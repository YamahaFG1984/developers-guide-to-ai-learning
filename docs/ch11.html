先建立基线

微调之前，先要知道模型什么都没学时表现如何 —— 这就是基线（baseline）。有了基线，才能衡量微调到底带来了多少提升。 我们用 zero-shot（prompt 里不给任何示例）测试三个模型：要微调的两个小模型，外加一个强大的商业模型 Google Gemini 作为参照。

zero-shot prompt
Classify the following email summaries into the following categories - * India Bank * India School * US Bank * US School The classification label should come before the summary test followed by a "-" <-- list of email summaries from the test dataset --->

微调分类模型：DistilBERT

先看全貌，再逐段看代码：

1. 导入与分词

from transformers import AutoModelForSequenceClassification   # 分类模型
from transformers import AutoTokenizer                        # 分词器
from transformers import TrainingArguments, Trainer           # 训练流程
from transformers import DataCollatorWithPadding              # 组装批次
from datasets import load_from_disk
import numpy as np
import evaluate                                               # 标准评估指标

model_id = "distilbert/distilbert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_id)           # 分词器必须和模型配套！

def preprocess_function(examples):
    return tokenizer(examples["text"], truncation=True)       # 太长的截断

dataset = load_from_disk("./data/mail_dataset_labeled")
tokenized_dataset = dataset.map(preprocess_function, batched=True)   # 批量处理，高效

map 会给每条数据加上 token ID 和 attention mask（注意力掩码）。

2. 动态填充与注意力掩码

Transformer 要求同一批（batch）里的序列长度相同，但邮件摘要长短不一。DataCollatorWithPadding 会把每批里较短的序列用特殊的 padding token 补到该批最长的长度：

data_collator = DataCollatorWithPadding(tokenizer=tokenizer)

accuracy = evaluate.load("accuracy")

def compute_metrics(eval_pred):
    predictions, labels = eval_pred                   # Trainer 评估时传进来
    predictions = np.argmax(predictions, axis=1)      # 取概率最高的类别 ID
    return accuracy.compute(predictions=predictions, references=labels)

3. 加载模型、设置超参数

label2id = {"IN_Bank": 0, "IN_School": 1, "US_Bank": 2, "US_School": 3}
id2label = {0: "IN_Bank", 1: "IN_School", 2: "US_Bank", 3: "US_School"}

model = AutoModelForSequenceClassification.from_pretrained(
    model_id, num_labels=4, id2label=id2label, label2id=label2id)   # 告诉它有 4 个类别

training_args = TrainingArguments(
    output_dir="trainer_output/my_mail_classifier",
    learning_rate=2e-5,
    per_device_train_batch_size=8,
    per_device_eval_batch_size=8,
    num_train_epochs=3,
    weight_decay=0.01,
    eval_strategy="epoch",
    save_strategy="epoch",
    load_best_model_at_end=True,
    push_to_hub=False,
    report_to="none",
)

控制训练过程的这些设置叫超参数（hyperparameters）：

参数一句话
learning_rate每次更新参数时“迈多大步”。太大会学乱，太小学得慢
per_device_*_batch_size每个设备一次处理几条。越大越吃内存，有时更快
num_train_epochs把整个训练集完整过几遍
weight_decay正则化：惩罚过大的权重，防止过拟合
eval_strategy / save_strategy"epoch"：每轮结束评估一次、保存一次
load_best_model_at_end训练完加载验证集上表现最好的检查点
push_to_hub / report_to不上传到 Hugging Face Hub、不向外部服务报告指标

4. 训练、保存、评估

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_dataset["train"],
    eval_dataset=tokenized_dataset["validation"],
    tokenizer=tokenizer,
    data_collator=data_collator,
    compute_metrics=compute_metrics,
)

trainer.train()                                  # 一行代码启动整个微调

trainer.save_model("models/my_mail_classifier")  # 保存，以后直接加载使用
⚠ 评估时换 pipeline 任务

微调后的模型要用 text-classification pipeline，而不是 zero-shot-classification。后者用于分类模型没训练过的类别；现在模型已经“认识”这些类别了。

微调 LLM 之前：几个概念

模型权重model weights模型内部的数值参数。训练就是在调整它们，它们共同代表了模型学到的模式和知识。
灾难性遗忘catastrophic forgetting在新任务上训练后，模型突然忘了原来会的东西 —— 新知识覆盖了旧知识。
用提示工程，当你
  • 资源或时间有限
  • 任务简单、需要快速上线
  • 没有训练数据或微调能力
用微调，当你
  • 需要最高性能
  • 任务复杂，要学深层知识
  • 有数据和资源，要适配特定领域

PEFT 与 LoRA：只训练一小部分

DistilBERT 用的是常规（全量）微调：所有参数都参与更新。对大模型来说，这极其昂贵，需要更多数据防止过拟合，还容易灾难性遗忘。 PEFT（参数高效微调）换了个思路：冻结原模型，只加一点点新参数来训练。

PEFT全量微调
什么时候用数据或算力有限；要快速训练和部署；想省存储；新任务和预训练任务相似数据和算力充足；要最大性能；新任务和预训练任务差别很大
优点更快更省；数据少时更不易过拟合；存储小；缓解灾难性遗忘数据充足时提升显著；实现简单
缺点有时达不到全量微调的效果；要仔细选 target modules昂贵耗时；需要更多数据；可能灾难性遗忘
🚗 LoRA 的比喻：给引擎加一块调校芯片

想按自己的驾驶习惯调校汽车引擎，不必拆开重造，只需要装一块小芯片，就能切换 eco / normal / sport 模式，引擎本身完全不动。 LoRA（Low-Rank Adaptation）就是这块芯片：在现有模型旁边加少量可调参数，实现高效微调。

LoRA 为什么能省那么多参数

LoRA 保持原来的大权重矩阵冻结，在旁边注入两个“瘦长”的小矩阵来学习变化量。最关键的设置是 rank（秩）r，它决定小矩阵有多“宽”：

LoRA 把这个技巧用在模型的许多关键层上。所有层加起来，可训练参数能从几十亿降到几百万。

⚡

更快更便宜

训练时间只是全量微调的一小部分，GPU 小时费用也更少。

💻

降低硬件门槛

内存需求大减，消费级硬件也能微调大模型。

📦

便携

产出一个 10–100MB 的小 adapter 文件，而不是一个 20GB 的新模型。一个基座可以挂多个 adapter。

🏆

质量不打折

效果可与全量微调相当，有时更好。

Chat Template：LLM 的“专属格式”

第 6 章我们用 messages 数组和模型对话。但模型实际看到的不是 JSON，而是一段带特殊 token的文本。 每个模型训练时用的格式都不同，这个格式叫 chat template（指令模板）。用错模板，模型就可能理解错你的输入。 

tokenizer = AutoTokenizer.from_pretrained(model_id)
print(tokenizer.get_chat_template())        # 查看模型的模板（它本身就是一个 Jinja 模板）

prompt = [
    {"role": "system", "content": "You are a helpful geography assistant. You are able to answer questions about the world."},
    {"role": "user", "content": "What is the capital of France?"},
    {"role": "assistant", "content": "The capital of France is Paris."}
]

print(tokenizer.apply_chat_template(prompt, tokenize=False))   # 看格式化后的文本
  • tokenize=False：返回格式化后的文本，方便查看模型期望的格式
  • tokenize=True：格式化后直接分词，返回 token ID
  • return_tensors="pt"：返回 PyTorch 张量，可以直接喂给模型
prompt = [
    {"role": "system", "content": "You are a helpful geography assistant. ..."},
    {"role": "user", "content": "What is the capital of France?"}
]
tokenized_input = tokenizer.apply_chat_template(prompt, tokenize=True, return_tensors="pt")
output_text = model.generate(tokenized_input, max_new_tokens=50)          # 最多生成 50 个新 token
print(tokenizer.decode(output_text[0], skip_special_tokens=True))         # 去掉特殊 token
# ... The capital of France is Paris.

让回答以指定前缀开头：continue_final_message

想让模型的回答以 “GA: ” 开头？直觉是在最后加一条 assistant 消息 {"role": "assistant", "content": "GA: "}。但结果是模型输出 “GA:” 就停了 —— 因为模板在这条消息后面加了回合结束标记。

tokenized_input = tokenizer.apply_chat_template(
    prompt,                                  # 最后一条是 {"role": "assistant", "content": "GA: "}
    tokenize=True,
    return_tensors="pt",
    continue_final_message=True,             # 关键：不加回合结束标记
)

构建 LLM 微调数据集

第 10 章的数据集是 text + label。LLM 要学的是“对话”，所以要把每条数据转成套好 chat template 的文本。训练集和测试集的格式不一样：

label_names = ["IN_Bank", "IN_School", "US_Bank", "US_School"]

def convert_to_training_messages(dataset):                   # 训练 / 验证用
    messages = [
        [
            {"role": "system",    "content": message_system},
            {"role": "user",      "content": f"Categorise: {ds['text']}"},
            {"role": "assistant", "content": f"Category: {label_names[ds['label']]}"}
        ] for ds in dataset
    ]
    texts = [tokenizer.apply_chat_template(m, tokenize=False) for m in messages]
    return {"text": texts}

def convert_to_prompting_messages(dataset):                  # 测试用
    data = []
    for ds in dataset:
        message = [
            {"role": "system", "content": message_system},
            {"role": "user",   "content": f"Categorise: {ds['text']}"}
        ]
        chat_message = tokenizer.apply_chat_template(
            message, tokenize=False,
            add_generation_prompt=True,                      # 末尾加上 assistant 开头，等模型作答
        )
        data.append({"text": chat_message, "label": ds["label"]})
    return {"items": data}

dataset = load_from_disk("./data/mail_dataset_labeled")
ds_train = Dataset.from_dict(convert_to_training_messages(dataset["train"]))   # 字典 → Dataset
ds_val   = Dataset.from_dict(convert_to_training_messages(dataset["validation"]))
ds_test  = Dataset.from_dict(convert_to_prompting_messages(dataset["test"]))

用 LoRA 训练 LLM

  1. 定义 LoRA 配置LoraConfig
  2. 把配置应用到模型get_peft_model
  3. 创建训练参数SFTConfig
  4. 训练SFTTrainer.train()

1. LoraConfig

from peft import LoraConfig

lora_config = LoraConfig(
    r=4,                       # 秩：adapter 有多“宽”
    lora_alpha=8,              # 缩放因子，实际缩放 = lora_alpha / r
    lora_dropout=0,            # adapter 上的 dropout，防过拟合
    bias="none",               # bias 参数保持冻结
    task_type="CAUSAL_LM",     # 因果语言模型：根据前文预测下一个 token
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",       # 注意力层
                    "gate_proj", "up_proj", "down_proj"],         # 前馈网络层
    modules_to_save=["lm_head"]                                   # 输出层也一起训练
)

2–4. 应用配置并训练

from peft import get_peft_model
from trl import SFTTrainer, SFTConfig

peft_model = get_peft_model(model, lora_config)   # 注入 adapter + 冻结原参数

training_args = SFTConfig(
    output_dir="trainer_output/my_mail_classifier_llm",
    report_to="none",
    overwrite_output_dir=True,
    do_train=True,
    learning_rate=2e-4,
    num_train_epochs=3,
    bf16=False,                                   # 关闭混合精度，用完整 float32 训练
    fp16=False,
)

trainer = SFTTrainer(                             # trl 库的监督微调训练器
    model=peft_model,
    args=training_args,
    train_dataset=dataset["train"],
    eval_dataset=dataset["validation"],
)

trainer.train()
trainer.save_model("models/my_llm_mail_classifier")   # 保存配置 + LoRA adapter 权重
  • get_peft_model 返回的模型用起来和普通 Hugging Face 模型一样，但训练时只有 LoRA adapter 里的少量参数会更新。
  • SFTTrainer 来自 trl（Transformer Reinforcement Learning）库，专为监督微调等“后训练”设计，和 LoRA 配合很方便。
  • 训练时间从几分钟到几小时不等，GPU 远快于 CPU。书中配置约 4.5 小时。

小结

阶段要点
建立基线微调前先测 zero-shot，知道提升空间，设定清晰目标
数据准备分类模型只需分词；LLM 需要套用各自的 chat template
高效适配LoRA（PEFT 的一种）冻结原模型、只训练小 adapter，大幅降低成本
执行与评估用 transformers、peft、trl 完成训练，用测试集证明价值

动手练习

  1. 调超参数：改 learning_rate、num_train_epochs 或 LoRA 的 r，观察训练速度、内存和最终准确率的变化。
  2. 换基座模型：从 Hugging Face Hub 选一个 Gemma 或 Llama 的变体，跑同样的流程，对比不同架构的表现。
  3. 不只看准确率：计算 precision、recall、F1，看看模型是否偏向某些类别。
  4. 试试 prompt 格式：改 LLM 训练数据里的 system prompt 或 user 指令，小改动可能带来明显的提升。
