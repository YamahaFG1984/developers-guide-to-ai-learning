全流程一览

收集原始数据

找数据集，不用看得比你自己的收件箱更远。如果你已经用标签或文件夹整理过邮件（紧急、收据、某项目……）， 挑 3–4 个类别、共几百封邮件。还没整理过的话，手动挑一些有代表性的邮件，贴上简单一致的标签。 目标是每个类别至少 50–100 封。这样训练数据才是真实的，和你的需求相关。

⚙ 自动化

手动复制几百封邮件太费时。大多数邮件服务都提供开发者 API，写个小程序就能把邮件连同你打的标签一起导出来。

把标签编码成数字

机器学习模型（包括 LLM）本质上只处理数字。文本会先经过分词变成数字序列（第 4 章），分类标签也一样要变成数字：

为什么要转数字说明
兼容性模型建立在数学运算之上，需要数值输入
效率训练时计算效率显著更高
避免误解防止模型从字符串之间“脑补”出不存在的关系
标准化Hugging Face 等框架和工具都期望这种格式

切分数据：训练、验证、测试

不能把全部数据都拿来训练。那样模型可能会把数据背下来，而不是学到通用的规律 —— 这叫过拟合（overfitting）。

解决办法是先打乱顺序，再切成三份，各司其职：

🔑 为什么要打乱？

防止模型学到“示例顺序”这种偶然规律。打乱确保模型学的是数据本身的特征，而不是它的排列，从而更好地泛化、避免偏见。

手工实现一遍，理解原理

import csv, random

random.seed(42)                                    # 固定随机种子，保证每次结果一样

data_in_bank = []
with open("rawData/in_bank.csv", "r") as f:
    for row in csv.reader(f):
        data_in_bank.append(row)
data_in_bank = data_in_bank[1:]                    # 去掉表头

random.shuffle(data_in_bank)                       # 打乱

n = len(data_in_bank)
train_end = int(n * 0.8)                           # 前 80%
test_end = int(n * (0.8 + 0.1))                    # 再 10%

data_in_bank_train = data_in_bank[:train_end]
data_in_bank_test  = data_in_bank[train_end:test_end]
data_in_bank_val   = data_in_bank[test_end:]       # 最后 10%

对四个文件都做一遍，会得到 4 × 3 = 12 个文件。但微调工具通常只要三个文件，所以还要按用途合并、再打乱一次：

用 Hugging Face Datasets 做同样的事

为什么不直接用 CSV？因为CSV 丢掉了关键的元数据：别人拿到 train.csv， 不会知道 label 列只能是那四个值之一。得另写文档说明，而文档很容易和数据脱节。 Datasets 库能把这些元数据直接嵌进数据集对象里。 

from datasets import load_dataset

dataset_in_bank = load_dataset("csv", data_files="rawData/in_bank.csv")
print(dataset_in_bank)

DatasetDict({                         # ❶ 数据集字典
    train: Dataset({                  # ❷ 默认全部数据都被标为 train
        features: ['text', 'label'],  # ❸ 列名自动变成“特征（feature）”
        num_rows: 100                 # ❹ 记录数
    })
})

feature（特征）是数据的一个可区分的属性，这里就是 text 和 label。接下来用 train_test_split 切两次，得到三份：

from datasets import DatasetDict

# 阶段 1：80% train / 20% 临时
ds_in_bank_train_test_split = ds_in_bank['train'] \
    .train_test_split(test_size=0.2, shuffle=True, seed=42)

# 阶段 2：把 20% 临时对半分成 validation 和 test
ds_in_bank_test_valid_split = ds_in_bank_train_test_split['test'] \
    .train_test_split(test_size=0.5, shuffle=True, seed=42)

ds_in_bank_split = DatasetDict({
    'train':      ds_in_bank_train_test_split['train'],
    'validation': ds_in_bank_test_valid_split['train'],
    'test':       ds_in_bank_test_valid_split['test']
})
# 对其他三个类别重复同样的步骤
🃏 shuffle 就像发牌前洗牌

它随机重排示例，每次顺序都不同；传入 seed 参数则保证同样的 seed 得到同样的顺序 —— 这对可复现很重要。

然后把四个类别的同名切分合并，再整体打乱：

给标签加上类型：ClassLabel

重新加载数据集，看看特征的类型：

from datasets import load_from_disk
ds = load_from_disk("./data/mail_dataset")
print(ds["train"].features)
# {'text': Value(dtype='string'), 'label': Value(dtype='string')}   ← label 只是普通字符串

技术上没错，但更好的做法是明确规定：label 必须是这四个值之一。 这就像给储藏室里的调料贴清楚标签 —— 一眼就知道这是“类别”而不是随便一个字符串，不会把糖当成盐。 

from datasets import ClassLabel

label_names = ["IN_Bank", "IN_School", "US_Bank", "US_School"]
label2IdMap = {"IN_Bank": 0, "IN_School": 1, "US_Bank": 2, "US_School": 3}

ds = ds.cast_column("label", ClassLabel(names=label_names))   # 转成 ClassLabel 类型
ds = ds.align_labels_with_mapping(label2IdMap, "label")       # 确保编号与映射一致

ds.save_to_disk("./data/mail_dataset_labeled")

ds_labeled = load_from_disk("./data/mail_dataset_labeled")
print(ds_labeled["train"].features)

{'text': Value(dtype='string'),
 'label': ClassLabel(names=['IN_Bank', 'IN_School', 'US_Bank', 'US_School'])}

小结

步骤要点
收集用真实数据（自己的邮件）；每类 50–100 条以上；可用邮件 API 自动导出
组织每个标签一个 CSV，两列：text + label
编码标签文本标签 → 唯一数字 ID，务必记录映射
切分打乱 → 80/10/10 → train / validation / test，防止过拟合
Datasets 库load_dataset → 两次 train_test_split → concatenate_datasets + shuffle → DatasetDict
类型安全cast_column 到 ClassLabel + align_labels_with_mapping

动手练习

  2. 练习另一种常见格式：创建一个 JSONL 文件，每行是一个带 text 和 label 的 JSON 对象，再用 load_dataset("json", …) 加载它。
