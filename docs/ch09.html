为什么以及何时定制模型

提示工程和 RAG 能解决大量问题，但总有一些任务，模型本身就不擅长 —— 再怎么调 prompt 也不稳定。 这时就该考虑微调（fine-tuning）了。本章没有代码，是一套帮你做决策的思考框架。

本章目标

  • 判断什么时候提示工程和 RAG 就够了，什么时候必须微调
  • 比较从零训练和微调的代价与收益
  • 认识三种微调策略：自监督、监督、强化学习
  • 认识两种微调方法：无代码和写代码
  • 记住微调的三个步骤：准备数据 → 微调 → 测试

故事：被淹没的收件箱

创业团队的 AI 客服很成功，RAG 让它第一次跑在了工单队列前面。他们乘胜追击：让 AI 顺便给收到的支持邮件按主题分类。 结果闸门一开，涌进来的远不止支持请求：

现有系统能检索、能回答，却不懂这家公司的邮件长什么样：它不会凭销售推销、客服工单、媒体询问在用词上的细微差别来判断意图。 这条路就是微调。

⚠ 数据集比什么都重要，也最难

微调需要大量正确标注的示例邮件。用强大的 LLM 生成合成邮件看似省事，但有隐患： 用大模型生成的数据来训练小模型，它可能很擅长分类“长得像合成数据”的邮件，在从没见过的真实邮件上却表现难料。 最可靠的数据往往是反映真实任务的数据 —— 也就是你自己的邮件。书中会教你在本机安全处理，不把邮件发到外部服务。

什么时候需要微调

面对“能力问题”，你有两条路：从零训练一个新模型，或者微调一个预训练模型。

从零训练 vs 微调

✅ 优点❌ 缺点
从零训练完全控制架构、设置和训练过程；可以为你的任务量身定制；不依赖任何外部模型需要海量标注数据；计算成本极高；需要大量机器学习专业知识
微调站在已有知识的肩膀上；需要的标注数据少得多；训练更快；更容易上手对架构和初始参数控制较少；可能继承原始训练数据的偏见；对非常独特的任务未必最优
选择从零训练，当你有
  • 一个要求非常独特的任务
  • 海量标注数据
  • 做大规模模型开发的专家和资源
选择微调，当你有
  • 有限的任务专属标注数据
  • 想借助已有知识、更快训练
  • 一个和预训练任务相对相似的任务
ⓘ 什么是 AI 中的“偏见（bias）”

模型持续产生扭曲结果或不公平倾向的系统性错误。它通常来自训练数据里的刻板印象、历史不平等或样本不具代表性。

三种微调策略

三种策略的区别在于：数据怎么标注，以及模型从什么样的反馈中学习。

🎓 用教孩子来类比
  • 自监督：给孩子一整座图书馆，让他猜每本书的下一个词 —— 今天的基础 LLM 就是这样训练出来的。
  • 监督：拿抽认卡教，一面是题目，一面是答案。
  • 强化学习：老师批改作业、打分，学生根据分数一遍遍修改。

两种微调方法

两种方法的区别在于需要多少技术细节和代码。

AutoTrain 也有命令行版本，一条命令就能启动一次分类模型微调：

autotrain text-classification \
--train \
--model distilbert/distilbert-base-uncased \
--project-name my-mail-classifier \
--data-path data/ \
--train-split train \
--valid-split valid \
--text-column text \
--target-column label \
--epochs 3 \
--batch-size 4 \
--lr 2e-5 \
--optimizer adamw_torch \
--scheduler linear \
--gradient-accumulation 1 \
--mixed-precision fp16

小结

  • 通用模型即使配上提示工程和 RAG，面对要求独特的高度专业任务也会力不从心。
  • 从零训练 vs 微调：控制力 vs 效率。大多数时候选微调。
  • 微调能借用已有知识、减少数据需求，微调过的小模型甚至能超越大模型。
  • 三种策略：自监督（模式）、监督（示例）、强化学习（反馈）。
  • 两种方法：无代码（AutoTrain）、写代码（Hugging Face 库）。
  • 三个步骤：准备数据 → 微调 → 测试。

思考题

  1. 回顾你工作中的一个 AI 需求：它是“知识问题”还是“能力问题”？该用 RAG 还是微调？
  2. 如果要为你的团队做一个邮件分类器，你的标签会是哪些？真实的标注数据从哪里来？
  3. 为什么只用大模型生成的合成数据来训练，可能导致模型在真实数据上表现不稳定？
