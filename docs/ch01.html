理解大语言模型

本章不写代码，只做一件事：把「LLM 到底是个什么东西」讲清楚。 搞懂它怎么被训练、怎么一个字一个字地“写”出答案、以及它在哪些地方靠不住， 后面十三章里的每一个技巧，你都能知道它是为了解决什么问题。

本章目标

  • 知道 LLM 是怎么训练出来的，训练数据从哪来
  • 理解“预测下一个 token”这个核心循环（自回归、推理）
  • 分清 AI 的概率性和传统程序的确定性
  • 记住 LLM 的四大局限：知识截止、幻觉、偏见、多步推理
  • 认识全书路线图：提示工程 → 上下文工程 → 微调 → 自建模型

LLM 是什么，怎么来的

大语言模型（Large Language Model，LLM）就是一个在海量文本上预训练过的超大深度学习模型。 训练数据包括网页、书籍、文章、论文、代码，再加上授权的数据源和人工整理过的数据集。

研究者发现了一件神奇的事：只要数据量足够大，模型就会“涌现”出理解语言、积累知识、甚至一定程度推理的能力。 没有人专门教它语法或常识 —— 它是从海量例子里自己“悟”出来的。

BERT：让模型学会“看上下文”

2018 年 Google 的 BERT 是今天 LLM 浪潮的起点之一。在它之前，模型很难理解复杂的句子结构。 BERT 的训练方法很像我们小时候做的完形填空：

除了完形填空，BERT 还练习判断两个句子是否前后相邻。这两招让它在问答、摘要上准确率大涨。

ⓘ 开源（Open Source）≠ 开放权重（Open Weight）

本书大量使用 Meta 的 Llama 3.2。它常被称为“开源模型”，但更准确的叫法是开放权重： 训练好的参数（权重）公开了，你可以下载运行；但完整源码、训练数据、训练过程并不一定公开， 许可证还限制了再分发和部分商业用途。真正的开源软件则是代码可以自由查看、修改、分享。

文本是怎么“写”出来的

这是整本书最重要的一个概念。LLM 生成文本的方式其实非常朴素： 预测下一个最可能出现的词，把它接上，再预测下一个，如此循环，直到结束。 每次预测的单位叫 token（第 4 章会细讲 token 和“词”的区别，现在先当成“词”理解就行）。

Tokentoken模型每次预测的最小单位，大致是一个词或半个词。
自回归auto-regressive一个接一个地生成，后面的词依赖前面所有的词。
推理inference模型拿到从没见过的输入（你的 prompt）并给出预测的过程。
Promptprompt你发给模型的文本，它就是生成开始时的“初始上下文”。

推理能力本质上就是泛化能力：训练一次，就能对全新的输入做出合理反应。 传统编程从来做不到这一点 —— 程序只会做你明确写过的事情。这也是 AI 真正有用的地方。

AI 和传统程序有什么不一样

传统编程AI 模型
基础布尔逻辑统计 / 概率
输出确定：同输入必得同输出不确定：同一 prompt 可能不同
灵活性只能做你写过的事能应对复杂规则和新情况
出错方式校验失败、抛异常 —— 错得很明显给出看似合理的错误答案 —— 错得很隐蔽

所以在决定用 AI 之前，先问自己两个问题：

  1. 我的业务能容忍回答有波动吗？prompt 写得再好，生成依然基于概率。
  2. 就算测试显示准确率 99.9%（也许比人还准），剩下 0.1% 出错时会造成什么后果？怎么兜底？
⚠ 什么时候需要“人在回路”（Human in the Loop）

决策越关键，越需要人来核验 AI 的输出。医疗、安全这类生命攸关的系统是最明显的例子： 只要有一丝可能导致严重伤害，就几乎必然要让人来做最后的确认。

一个模型，很多用途

模型从来没有为你的具体需求专门训练过，但它却能帮你写邮件、做翻译、写代码。 秘密在于两步训练：预训练学会通用的“预测下一个词”， 指令微调（instruction-tuning）学会听指令、给出有帮助且格式良好的回答。 于是只要一个清晰的 prompt，同一个模型就能胜任很多任务，无需重新训练：

必须正视的四大局限

AI 研究的终极目标是通用人工智能（AGI），但 LLM 不是 AGI，至少现在还不是。 别掉进“手里拿着锤子，看什么都像钉子”的陷阱。下面四个局限，决定了本书后面所有技术存在的意义：

局限 1：训练知识有截止

模型的知识被“训练数据截止日期”框死了。问它最新的新闻、你公司内部的产品文档， 它要么不知道，要么给出过时、残缺却很自信的答案。

解法很直接：在推理时把它缺的信息放进 prompt 里。这叫 AI grounding（接地）。 比如一个客服机器人，我们把相关的知识库文章一起发给模型：

接地示例：把知识库文章塞进 prompt
Instruction: Only use the following articles to answer the question. Context: Knowledge base articles - How to reset your password - Logging in with a password and MFA Question: I'm having password issues. Can you help me log in?

局限 2：幻觉

如果模型没学过你问的东西，它不会说“不知道”，而是根据见过的模式照样拼出一串 token， 语气笃定，甚至编造事实。书里有个很妙的类比：你和人聊天，自以为懂了对方在说什么， 自信地发表了一通高见，结果对方看你像看外星人 —— 你把记忆碎片拼成了一个并不适用的答案。

幻觉也来自 LLM 的概率本质：即便是高概率的 token，放在特定语境里也可能是错的。 幻觉永远可能发生，我们能做的是降低它的概率（第二部分会讲一系列技巧）。

局限 3：模型偏见

训练数据本身就带着人类的偏见和盲区。如果数据以英语、某些地区的内容为主，或者重复了刻板印象， 模型就会复现这些模式。这不是模型“选择”不公平，而是它在照搬所见 —— 它学的是语言模式，不带道德判断。对策是加过滤、调整 prompt，或者微调模型。

局限 4：多步推理

LLM 并不像人那样“思考”，它只是按模式生成下一个可能的词，没有计划。于是：

  • 会跳步骤、混淆事实，做出“看着对其实错”的自信跳跃
  • 误差累积：第一步错了，后面全部建立在错误之上
  • prompt 越长越糟糕：重要细节被淹没，模型用猜测填空，而不是主动问你
  • 没有可靠的自检：不知道自己错了，除非你要求，它不会验算
  • 跨轮次没有真正的工作记忆，长任务中上下文会漂移

提升效果的四层金字塔

LLM 本质上是个黑盒，我们不知道它到底学过什么。对任何预训练模型，都得实验才知道开箱即用够不够。 老话依然成立：Garbage in, garbage out。当效果不够好时，按下面的顺序一层层往下走：

提示工程

在 prompt 里给出上下文、指令、示例，让模型理解意图。需要创造力和反复试错。最便宜，永远先试它。

上下文工程

提示工程 + 管理上下文的系统组件：只放需要的事实，按清晰顺序排列。聊天机器人和 Agent 尤其重要。

微调

拿一个已经很强的模型，用你的专业数据继续训练，把它塑造成你需要的样子。

自建模型

从零训练。我们是“AI 厨师”，用现成的原料做菜；造模型留给“AI 建筑师”。

🔑 什么是上下文工程？

Andrej Karpathy（OpenAI 联合创始人）的说法：人们以为 prompt 就是一段简短的任务描述， 但在任何工业级 LLM 应用里，上下文工程是一门精细的艺术与科学 —— 用恰到好处的信息填满上下文窗口，以支撑下一步。 上下文窗口就是一次能发给模型的最大 prompt 长度（第 4 章详述）。

走向自主系统

传统软件按固定方式编程，任何新流程都要改代码。 智能体 AI（Agentic AI）不一样：它能自己做决策、采取行动、调整行为，通过调用工具、API 甚至其他模型来完成复杂任务。

  • Agent（智能体）是最常见的实现模式
  • MCP（Model Context Protocol）是让工具、API、数据源能被 AI 模型访问的开放标准

这两个概念会在第五部分（第 12–14 章）展开。
